# HMW 上下文状态台账

> 2026-11-17 建立。本页用于**识别过期假设和显式记录取代关系**，不再把旧 PR/聊天/设计猜想隐性视为命令。当前规范以 [ACTIVE.md](ACTIVE.md) 为准；本页不另立竞争的需求入口。

## 何种信息具有约束力

| 状态 | 意义 | Agent 应如何处理 |
|---|---|---|
| **有效决定** | 用户当前认可的产品目标、职责或安全边界 | 依 ACTIVE 执行；拟改变先解释影响并更新 ACTIVE |
| **已验证事实** | 某提交/环境/时刻有可重复证据 | 可引用，但必须带版本、环境和覆盖范围，不能外推到未来 |
| **待验证候选** | Draft PR、局部实验、产品假设 | 可以检索与复用；验证依赖后再合并，不以历史存在为必须实施 |
| **已取代/失效** | 与当前目标冲突或已过时的顺序、方案、结论 | 留档供追踪，但不得当成待办指令 |

## 已取代/停止当作命令的内容

| 旧说法 | 取代后的处理 |
|---|---|
| “每轮从旧任务清单逐项挑一个功能、必须提交代码” | 以用户目标与真实障碍判断是否值得修改；无证据不编造改动 |
| “固定表单布局、指定某几个字段/插件作为永久开发顺序” | 原版 Hop 和真实用户任务可作比较对象，但 UI 形式与优先级开放探索 |
| “Schema 非空、原样保存、Smoke 通过 = 专业可用/产品完成” | 只算对应有限证据；真实业务改值、原生重开与用户体验另测 |
| 旧文中的 main/Java SHA、槽位版本、服务器剩余容量 | 视为当日快照；每次操作前核验现场 |
| 2026-11-14 [产品交付板](product-delivery-board.md)和 2026-11-15 [ACTIVE 旧版](archive/ACTIVE-20261115-before-context-reset.md) 的“下一步” | 保留出处，不当作本轮任务与优先级 |
| 旧 E2E 单纯固定四条 = 全部产品质量 | 继续四条硬性回归，另以开放式探索验证真实任务 |

## 修改规则

1. 用户明确改变目标：先在 [ACTIVE.md](ACTIVE.md) 一次性改写**完整当前要求**，不要尾部叠加互相冲突的补充提示。
2. 旧决定与新决定冲突：在本页注明“旧 → 新”及理由；留历史链接但停止强制旧方案。
3. 具体 PR 仅按验证风险做正常审查，不因新阶段重置而自动合并，也不因旧而自动舍弃。
4. T5 汇总独立证据；T1–T4 自主寻找改善机会。修复和验收标准保持职责分离，便于识别测试误报。
5. 只有实际复核的运行结果可以标为“已验证”；腾讯云无法访问时不得用 GitHub 静态代码替代运行证据。
