# HMW · 当前产品目标与执行基线

> 2026-11-17 重整。**本文件是第二轮五任务的唯一当前产品/职责入口**。修改当前要求时直接修订本文件，不再在旧提示词末尾叠补丁；技术事实以运行时和 GitHub 最新提交/证据为准。历史决定与已废止假设见 [上下文状态台账](CONTEXT_LEDGER.md)。

## 使命

让真实用户在浏览器中建立、理解、修改和管理 Apache Hop Pipeline / Workflow 及原生业务配置，并逐步具备可信授权的数据库连接管理、执行与结果查看能力。产品目标是用户能独立、正确、顺畅地完成任务，而非代码数、PR 数、插件字段数量或测试绿灯。

实现方法保持开放：从实际用户旅程探索问题，比较原版 Hop 与当前 Web 的差异，自主选择有证据的方案。不得把某次 UI 方案、像素规格、旧 Issue 排期或历史 PR 转化为永久要求。

## 不变的交付底线

- 使用真实 Apache Hop 原生模型、插件、元数据与 `.hpl/.hwf`，保存后应能由官方 Hop 独立重新解析；不能以假页面或仅 HTTP 200 冒充闭环。
- 保护未提交文件、用户数据、工作区和秘密。未有可信每用户身份/授权证据时，原生数据库管理和执行入口保持 fail-closed；不以槽位、IP、伪造用户头或前端静态凭证代替授权。
- 取消不应写盘，保存失败应清楚提示且尽量保留草稿；409/503、并发竞争、路径越界、符号链接等风险需按具体变更范围验证。
- 不能通过削弱测试、删失败 Trace 或修改标准制造成功；将**已合并、已部署、在真实环境验证、仅提出**明确区分。
- 工程架构参考 [Apache Hop 原始现代 Web 架构方案](https://github.com/cxhttt233/hop/blob/design/web-modern-architecture/docs/web-modern-architecture-plan.md)。如发现更好方案，可提出并进行有证据的评估，不擅自破坏原生兼容与安全边界。

## 五个稳定责任域

| 任务 | 长期目标与独占职责 |
|---|---|
| **T1 可信安全** | 受信身份、权限、文件/工作区隔离与原生 DatabaseMeta 安全管理；不开发 Schema/表单 |
| **T2 Workflow** | `.hwf` 的新建、Action 原生业务/图与生命周期、失败恢复；Action 配置**表单生成器**不属于 T2 |
| **T3 专业表单** | **唯一端到端负责人**：Transform + Workflow Action 的 Java Meta/i18n → FormSchema → 通用 React 专业布局/控件 → 真实改值/持久化/批量评估 |
| **T4 图与全局体验** | 非表单画布、拖拽/连接、导航/快捷键、状态表达和竞争恢复；不得改 T3 的生成器或表单 |
| **T5 总集成与独立评价** | 集成 PR、预览和运行环境、跨模块安全/原生 E2E、用户目标驱动及开放式体验探索；不替 T1–T4 实现专属业务 |

T1–T4 先自己使用本模块完成一个目标，主动寻找最高价值的实际障碍，而非机械照旧工单开发；T5 独立验证、反馈问题与影响，不预先规定实现布局。体验评价应提供用户路径和可观察证据，不用不可信的主观总分替代判断。

## 第二轮交付方法

1. **先校准**：查最新 GitHub main、自己负责的代码、候选 PR、实际预览/Java 版本和已有证据；历史 SHA 只是快照，不得当作当前环境。
2. **先体验后决定**：以用户要完成的任务为起点。可以选择实现、修复、比较方案或结论为“证据不足”，不以每轮必须提交 PR 为目标。
3. **在独立工作树推进**：五个第二轮 GitHub 起始分支 `cycle/20261117-t1-security`、`cycle/20261117-t2-workflow`、`cycle/20261117-t3-forms`、`cycle/20261117-t4-canvas`、`cycle/20261117-t5-integration`。分支名是起始工作区，不是永久锁定 SHA；新功能可从更新后的 main 建临时分支。旧分支/PR 作为候选资产，不强制合并/删除，不动别人的未提交改动。
4. **分层验证**：保留确定性安全与原生回归；对受影响能力增加真实浏览器用户目标测试；开放式探索只生成可复核发现。按变更风险执行，避免每小时重复全量 E2E。T5 进行独立复测，开发者不得自行降级门禁。
5. **报告真实结果**：每轮报告实际用户任务、发现、变更与 SHA、原生/浏览器证据、仍未验证项，以及下一件最有价值的事。连不上测试机则如实报告，不能将连接异常冒充产品失败。
